FundedFrens Telegram Bot — Stability & Backend Synchronization (Priority Update)

This session is not about redesigning the bot.

The UX redesign has already been completed.

This task is focused on making the bot accurate, reliable, fast, and fully synchronized with the FundedFrens backend.

The website remains the single source of truth.

Push every completed change back to the frensbot repository only.

Repository:

⸻

Primary Goal

The Telegram bot should behave like the official trading terminal for FundedFrens.

The website manages accounts, challenges, analytics and funding.

The bot manages trading.

Everything must stay synchronized through Supabase.

⸻

1. Make Supabase the Source of Truth

Stop assuming values.

Stop creating fake defaults.

Stop hardcoding challenge information unless absolutely necessary.

Whenever possible:

• Read from Supabase.

• Write back to Supabase.

The bot should become another client of the FundedFrens backend—not its own isolated system.

⸻

2. Challenge Balance Logic

The current balance behaviour is inconsistent.

Replace it with a deterministic system.

When a user purchases or receives a challenge:

• Read the challenge information from Supabase.

• Determine the challenge value.

• Convert that value into SOL once using the current SOL/USD price at the moment the challenge is created or activated.

• Store that SOL value in Supabase.

That stored value becomes the user’s starting challenge balance.

Do NOT keep recalculating the initial balance whenever SOL price changes.

From that point onward:

Current Balance =

Starting Challenge SOL

* Realized Profit

* Realized Loss
* Current Open Exposure

The initial challenge balance should remain fixed.

Only trading results should move the balance.

This ensures challenge balances remain stable even if SOL doubles or halves in price.

⸻

3. Trading Results

Every completed trade must immediately update Supabase.

At minimum record:

• Realized Profit/Loss

• Profit %

• Position size

• Entry price

• Exit price

• Entry time

• Exit time

• Hold duration

• Market Cap

• Liquidity

• Volume

• Trade status

• Trigger source

After each trade:

Update challenge analytics.

Update account statistics.

Update buying power.

Update challenge progress.

Everything visible on the website should stay synchronized.

The website analytics must always reflect what happened inside the bot.

⸻

4. Helius Must Become Primary

Helius is now the primary provider.

Use Helius first for:

• Token lookup

• Metadata

• Images

• Symbols

• Verification

• Token information

Use DexScreener only when Helius cannot provide the required information.

Never skip directly to DexScreener.

The bot should almost never fail to recognise a valid Solana token.

⸻

5. Fix Contract Detection

This is one of the highest priorities.

Currently pasting some contract addresses returns nothing.

This should never happen.

Investigate why.

Support:

• Raw Solana contract addresses

• Pump.fun URLs

• DexScreener URLs

• Birdeye URLs

• Solscan URLs

• Token tickers

As soon as any valid token identifier is pasted, immediately load the token page.

No Buy command.

No additional prompts.

Make this extremely reliable.

⸻

6. Remove Auto Take Profit

Remove it completely.

Remove:

• Auto Take Profit

• Auto Sell

• Automatic profit exits

Nothing should ever sell automatically because the user never explicitly requested this behaviour.

Only keep:

• Manual Sell

• Stop Loss (if explicitly configured)

• Trailing Stop (only if intentionally enabled by the user)

The bot should never invent risk settings.

If the user did not configure one, then none should exist.

⸻

7. Stop Auto Deleting Messages

The bot currently deletes previous messages.

Remove this behaviour.

Allow the conversation history to remain visible.

Do not continuously edit or replace previous screens.

The bot should feel more natural and easier to follow.
